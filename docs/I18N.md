## Switch on a standby language (about 30 minutes plus review)

1. Copy `app/locales/en/` to `app/locales/<code>/` (for example `app/locales/hi/`).
2. Translate the values in `ui.json` and `content.json`. Keep every key, every `{placeholder}` and every list length. Plural entries (`{"one": …, "other": …}`) can get extra forms (`few`, `many`) where the language needs them.
3. Edit `meta.json`: `{"status": "machine"}` until a native speaker has checked it, then `"reviewed"`.
4. Add the code to `ENABLED` in `app/i18n.py`.
5. Run `python -m app.check_locales <code>` — it must print `OK`.
6. Run `python -m unittest` and open a few pages and a PDF in the new language.

Arabic (`ar`) is already set up for right-to-left: the layout, charts and Word/PDF files mirror automatically.

## Adding a brand-new language

Add one entry to `LOCALES` in `app/i18n.py` (native name, direction, script, Babel locale, voice codes, default currency, Word language tag), then follow the steps above.

## How translation works in the app

- Interface text: `t("key", locale)` → falls back to English, never shows a raw key; misses are logged to the `missing_translations` table and listed in Settings.
- Generated project content (tasks, risks, documents) is stored as keys, so it shows in every language at once.
- Text typed by users or written by Claude stays in the project's language. With a Claude key, Tasks → “Translate tasks into …” creates machine translations in `content_translations`; they are marked machine-translated and flagged when the original text changes.
- Numbers, dates and money are formatted with Babel per language; values are never converted.

## Adding a guided-tour step

Add `{ page: '<page>', sel: '#element-id' }` to `STEPS` in `app/static/app.js` and the strings `tour.s<N>_t` / `tour.s<N>_d` to every `ui.json`.
